# 方法与面试准备

## 你需要能解释的六件事

1. **为什么做质量审计？** 机器人轨迹是状态、动作、时间与视频的序列。文件能打开，不代表序列完整或适合训练。结构错误可以自动确认，统计异常需要复核，任务失败也可能是一条有效的训练数据。
2. **为什么不用任务文本？** 当前转换版失败轨迹没有文本，成功轨迹有文本。利用“是否为空”就能猜标签，却无法证明模型理解机器人动作。项目使用明确的运动特征白名单。
3. **为什么只看前 30 帧？** 避免终局信息变成答案。按最终长度截取 20% 也可能泄漏结束时间，因此使用固定观测长度。短于 30 帧的演示排除并报告，结果只适用于达到该观测长度的演示。
4. **为什么按采集者划分？** 同一人的习惯、机械臂摆位和采集方式会同时出现在很多轨迹中。随机拆帧或随机拆轨迹可能让模型记住这些相似性。分组测试更难，但更接近对新采集者的应用。
5. **为什么需要随机剔除对照？** 清洗后样本数量变少，训练分布也会改变。只有同时比较随机剔除、审计剔除和理想剔除，才能区分数量影响、检测质量和可达到的上界。
6. **为什么 AUC 没到 0.85 仍有研究价值？** 项目已经限制了观察长度与泄漏渠道。实际结果显示早期运动的预测能力有限，而且验证集的模型排名不一定延续到新采集者。应解释这个现象和证据边界，不通过反复查看测试集修改模型来追求漂亮数字。

## 代码阅读顺序

- `paths.py`：为什么环境、缓存和输出需要显式定位；Windows 的扩展路径与目录穿越防护。
- `download.py`、`data.py`：固定数据版本、断点下载、哈希、冲突标签隔离与数据抽样。
- `features.py`：运动特征、前缀限制，以及为什么不对四元数直接做普通差分。
- `audit.py`：结构检查、全轨迹质量摘要、训练集拟合的异常检测与采集者分组。
- `modeling.py`：训练／验证／测试的职责、失败类别指标与分组 bootstrap。
- `policy.py`：人工污染、五组训练、可恢复断点、匹配初始状态，以及对训练种子和共享初始状态做双向分组重采样的置信区间。

## 关键术语

| 术语 | 这个项目中的含义 |
|---|---|
| Episode | 一次完整的机器人演示，包含很多帧；不是一帧一条样本 |
| Success prediction | 从固定早期轨迹预测这次人类演示最终成功与否 |
| ROC-AUC | 跨分类阈值的排序能力；0.5 是常数预测的基准 |
| Failure PR-AUC | 把失败作为关注类别时，精确率与召回率曲线的平均精确率 |
| Review flag | 待复核标记；并不等价于已确认损坏 |
| Contamination | 在仿真实验训练数据中人工注入的动作错误，有独立答案记录 |
| Percentage points | 成功率 50% 到 60% 是提高 10 个百分点；相对提高为 20% |

## 诚实的贡献描述

这是基于公开数据和开源仿真器的独立工程研究项目。你可以描述自己设计、实现、运行并理解的数据管线和实验。不能把 DROID 数据采集、robomimic 数据集、MuJoCo 仿真器或论文算法说成自己的原创；没有真实机器人部署，就不能写生产机器人性能提升。
